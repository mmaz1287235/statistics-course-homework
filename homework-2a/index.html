Encryption, Cryptanalysis
and Small Key Spaces

I compare a Caesar cipher with a simplified encryption scheme using secp256k1. I also test how easily their keys can be recovered.

Scope. This is an educational ECIES-inspired construction, not standardized ECIES or a production encryption library. The private and ephemeral scalars are intentionally small and insecure. Never enter secrets.

Homework 2A: real curve

Use the actual secp256k1 domain parameters and Q = kG, but deliberately constrain the chosen receiver scalar to 1…4096. This is not the toy curve from HW1.

New capability

Scalar multiplication is not encryption. We add an ephemeral public point, an ECDH shared point, SHA-256-based message masking and HMAC verification.

For each run, choose r uniformly from 1…4096 using browser randomness, calculate S = rQ = kR, and derive separate SHA-256 domain-separated masking and MAC keys from S and R. Mask UTF-8 bytes using SHA-256 blocks indexed by a counter. The receiver verifies the tag before decryption. This construction is intentionally not a standard KDF/AEAD and is insecure for real use.

    07

    Attack restricted-key ECC

    Search public keys Q = 1G, 2G, …, 4096G to find the receiver scalar.

    Recovered key and messageRun an ECC encryption first.

    This exact-match attack uses repeated point addition, rather than 4096 independent scalar multiplications. It finds a receiver key that matches the public point, then authenticates and decrypts the previously generated ciphertext. The experiment attacks only this intentionally bounded system. Against an unrestricted secure secp256k1 key sampled from a space of about 2²⁵⁶ possibilities, direct linear search is not feasible; generic square-root discrete-log attacks still require astronomical resources.

    08

    Interpretation and limitations

    Why the two attacks are fundamentally different.

    Language statistics vs algebra

    In my Caesar experiment, I score all 26 shifts using English letter frequencies. Longer ciphertexts usually give more reliable estimates, although success still depends on the writing style. The ECC attack is different. It compares calculated public points with the target point, so it does not use language statistics. A matching point identifies the private scalar within the tested range.

    It is also possible to try all 26 Caesar keys directly. The difficult part is deciding which output makes sense. Letter frequencies provide one practical way to make that decision.

    What is weakened?

    I deliberately restricted the receiver key to 4,096 possible values, which makes exhaustive search practical. The ephemeral scalar r is just as small. An attacker could recover r from R = rG and compute rQ to decrypt the message without finding k. Both choices make this demonstration insecure. Real applications require an established encryption scheme, properly generated keys and authenticated encryption.

    The measured Caesar success rates depend on the news corpus, the text length and the testing method. The ECC search time also depends on the device and browser. These experiments explain specific weaknesses, but they do not provide a general security assessment.
